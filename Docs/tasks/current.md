## 任务六：面板选中响应速度与选中态视觉优化

### 背景（用户实测反馈）

1. 鼠标点击卡片切换选中项有 ~0.5s 延迟感，期望“秒选中”；
2. 面板唤出后搜索框默认聚焦（输入态光标），期望默认 icon 态，点击后再进入输入态；
3. 选中态视觉不显眼，普通卡片与选中卡片都和背景糊在一起。
   视觉参考 tw93/Kami 的设计语言（规格见 UI.md §5.1，勿引用其代码）。

### 子任务 A：选中延迟优化

**根因假设（按可能性排序，逐一排查，排查过程写进汇报）：**

1. **滚动动画拖累**：当前 `onChange(of: effectiveSelectedID)` 对任何选中变化
   （含鼠标点击）都 `withAnimation { proxy.scrollTo }`——点击本就在视野内的卡片
   时，无意义的有动画滚动造成“延迟感”。
   **修法**：滚动仅当选中项不可见或变化来自键盘导航时执行；鼠标点击可见卡片
   不触发滚动。键盘导航保留平滑滚动。
2. **全列表重渲染**：`effectiveSelectedID` 变化使全部 `CardView` 重求值；
   若图片缩略图每次渲染都从磁盘重载即为卡顿主源。
   **修法**：缩略图进 `NSCache`（以 payloadPath 为键）；`CardView` 尽量
   `Equatable`/减少依赖面，确认选中变化不触发图片重解码。
3. **事务动画继承**：选中状态变化若被外层 `.animation` 捕获，描边/缩放会以
   默认时长动画，视觉上像“慢半拍”。
   **修法**：选中态样式变化禁用隐式动画（显式 `animation(nil)` 或
   事务级 `.withTransaction`），如需过渡显式指定 ≤0.1s。

**验收（A）：**

- A1: `xcodebuild test` 全过；新增单测：点击选中**不**触发滚动请求的判定逻辑
  （抽纯函数判断“选中变化是否需要滚动”：来源 × 目标可见性）。
- A2: Debug 编译 0 error 0 警告。
- B1（人工）：点击视野内卡片，高亮**当帧**切换、无滚动动画拖影；快速连续点
  击 10 张卡片无累积卡顿；键盘 ←/→ 导航仍有平滑滚动且自动滚到可见。

### 子任务 B：搜索框默认不聚焦

- 移除唤出时的自动聚焦（`focusSignal` 相关逻辑评估后删除或改语义）。
- 搜索框未聚焦时呈现 icon 态外观（放大镜图标 + 提示文字，无边框输入态）。
- **保留**键入字符即聚焦并填入的交互（UI.md §2.3 已修订：按字符键聚焦搜索框
  并追加该字符）——在面板级 `onKeyPress` 中处理可打印字符。
- 面板级 ←/→/Return/Esc 不依赖搜索框聚焦照常工作。

**验收（B）：**

- A1: 新增单测：字符键路由逻辑（可打印字符 → 聚焦搜索 + 追加；功能键 → 不追加）。
- B1（人工）：唤出面板无文本光标；点搜索框进入输入态；直接按字母键自动聚焦
  并过滤；方向键/Return/Esc 无聚焦时也正常。

### 子任务 C：选中态与配色（按 UI.md §5.1 实现）

- 三层层次：面板底色 / 普通卡片 / 选中卡片；浅色走 Kami 暖纸 + 墨蓝方案，
  深色走深暖灰 + 浅钢蓝方案（色值见 §5.1，须深浅色都成立）。
- 选中态 = 2pt 描边 + 8% 强调色填充 + ≤1.02 缩放；禁渐变/重阴影。
- 全部样式进 `Theme/Theme.swift` 语义化命名，视图中无魔数。

**验收（C）：**

- A1: 编译通过、测试全过；Theme 中无常量被视图文件内联覆盖（grep 自查汇报）。
- B1（人工）：浅色模式下选中卡片一眼可辨、与背景分层清晰；切深色模式同样
  成立；截图对比附汇报。
